# CodeWidget 自动测试实施说明及报告

本文档描述了 CodeWidget 项目的自动化测试体系架构、测试覆盖范围以及当前的测试状态。

## 1. 测试技术栈

项目采用了现代 Python 测试工具链，保证了代码质量和跨平台稳定性：

| 组件 | 技术 / 库 | 职责 |
|------|-----------|------|
| **测试框架** | `pytest` | 核心测试运行器，支持断言、Fixtures 等 |
| **GUI 测试** | `pytest-qt` | 提供 `qtbot` 用于在测试环境下安全地创建和操作 PySide6 控件 |
| **依赖管理** | `uv` | 管理虚拟环境，确保测试在隔离且一致的环境中运行 |
| **导入配置** | `pyproject.toml` | 通过 `pythonpath = ["src"]` 确保源代码对测试可见 |

## 2. 测试目录结构

测试代码位于 `tests/` 目录，与业务逻辑（`src/`）一一对应：

```
tests/
├── test_scheduler.py       — 排课引擎核心逻辑测试
├── test_override.py        — 调课规则应用与重编号测试
├── test_attendance_window.py — 出勤码展示窗 GUI 逻辑测试
├── test_config_dialog.py   — 设置对话框 UI 行为测试
├── test_tray.py            — 系统托盘状态更新测试
└── __init__.py
```

## 3. 测试覆盖范围

### 3.1 核心引擎逻辑 (Engine Logic)
- **Resolved Course Schedule**: 验证不同课程类型（春/秋/Q系）生成的授课次数（14次）和日期的准确性。
- **Override Application**: 验证停课（skip）、补课（makeup）、调课（reschedule）规则被正确应用，并确认 `session_key` 在调课后能正确重新编号。
- **Window Computation**: 验证课前/课后显示窗口的计算（默认 10/30 分钟）以及活动课程的命中逻辑。

### 3.2 界面交互 (GUI Interaction)
- **AttendanceWindow**: 验证课程信息（课程名、回次）是否正确渲染到标签和输入框中；验证窗口创建后初始为隐藏状态。
- **ConfigDialog**: 验证对话框可成功实例化；验证标签页数量（5个）、课程表列数（5列）、年度列内容（"2026"）；验证调整标签页的操作按钮集合（"調整を追加"、"編集"、"削除"）。不包含用户操作模拟（无 `qtbot.mouseClick`）和保存流程测试。
- **TrayIcon**: 验证托盘 ToolTip 随课程状态（无课/有课）的动态变化。

## 4. 引擎层可测试性原理：以 `compute_window` 为例

### 4.1 函数不从 UI 取值

`compute_window` 是一个**纯函数**，其三个参数全部是启动时从配置文件读入内存的数据对象，与任何 UI 组件没有引用关系：

```python
def compute_window(
    sc: ScheduledClass,        # 一节具体课程（日期 + 时限编号）
    school_config: SchoolConfig,   # 时限表（"08:50" 等时间来自这里）
    settings: Settings,        # pre/post_class_minutes 来自这里
) -> tuple[datetime, datetime]:
```

各参数的数据来源追溯如下：

```
school_config.json          teacher_config.json
      │                            │
      ▼                            ▼
  SchoolConfig                 Settings
  .periods["1"].start          .pre_class_minutes = 10
   = "08:50"                   .post_class_minutes = 30
           ↘                 ↙
        compute_window(sc, school_config, settings)
           ↓
    window_start = 08:40
    window_end   = 09:20
           ↓
    AttendanceWindow（UI 仅展示结果，不参与计算）
```

### 4.2 单向数据流

整个调用链是单向的：配置文件 → 内存模型 → 引擎函数 → UI 展示。
引擎层（`engine/scheduler.py`）**不 import 任何 PySide6 模块**，对 UI 的存在完全不知情。

```
main.py 启动
  ├─ load_school_config()  → school_config（内存对象，只读）
  └─ load_teacher_config() → teacher_config.settings → Settings(pre=10, post=30)

_tick()（每30秒）
  └─ get_active_class(now(), all_scheduled, school_config, tc_settings)
           └─ compute_window(sc, school_config, tc_settings)
                    ← 纯函数，无任何 UI 依赖
```

### 4.3 解耦带来的可测试性

正因为引擎层与 UI 完全解耦，`test_scheduler.py` 中的测试可以**直接传入构造好的数据对象**，无需启动 Qt 环境：

```python
def test_period1_window(self, school, teacher):
    sc       = sorted(resolve_course_schedule(course, school), ...)[0]
    settings = Settings(pre_class_minutes=10, post_class_minutes=30)
    ws, we   = compute_window(sc, school, settings)
    assert ws == datetime(2026, 4, 16, 8, 40)
    assert we == datetime(2026, 4, 16, 9, 20)
```

同理，`get_active_class` 的边界值测试（`08:39` 返回 `None`，`08:40` 返回课程对象）也不需要任何 GUI，秒级完成。

| 层级 | 依赖方向 | 测试方式 |
|------|---------|---------|
| `engine/` | 只依赖 `models/`，不依赖 `gui/` | 标准 pytest，无需 Qt |
| `gui/` | 依赖 `engine/` 和 `models/` | pytest-qt + `qtbot` |
| `main.py` | 集成所有层 | 未纳入自动化测试 |

## 5. GUI 测试原理：以 `pytest-qt` 为例

### 5.1 核心工具：`qtbot`

pytest-qt 插件向每个测试函数自动注入 `qtbot` fixture，其背后完成两件事：

1. **保证 QApplication 存在** — Qt 要求所有 Widget 必须在 `QApplication` 实例存在时才能创建。pytest-qt 在测试开始前自动创建，测试结束后销毁。
2. **`addWidget(win)` 负责清理** — 将 widget 注册给 qtbot，测试结束后由 qtbot 调用 `win.close()` 并释放内存，防止 widget 泄漏影响后续测试。

```python
def test_update_class_sets_labels(qtbot, sc):
    win = AttendanceWindow()
    qtbot.addWidget(win)        # 注册，测试结束后自动清理
    win.update_class(sc)
    assert "初年次セミナーA" in win.label_course.text()
```

### 5.2 测试"状态"而非"像素"

本项目的 GUI 测试不截图、不比较视觉外观，而是**直接读取 widget 对象的属性**：

| 测试目标 | 读取方式 | 测试示例 |
|---------|---------|---------|
| 标签文字 | `label.text()` | `assert "初年次セミナーA" in win.label_course.text()` |
| 输入框内容 | `edit.text()` | `assert win.code_edit.text() == "5678"` |
| 窗口可见性 | `widget.isVisible()` | `assert not win.isVisible()` |
| 标签页数量 | `tabs.count()` | `assert dlg.tabs.count() == 5` |
| 按钮集合 | `findChildren(QPushButton)` | `assert labels == {"調整を追加", "編集", "削除"}` |

### 5.3 三个 GUI 测试文件的具体内容

**`test_attendance_window.py`** — 调用 `update_class()` 后检查 widget 属性：

```python
win.update_class(sc, "5678")
assert win.code_edit.text() == "5678"   # Qt Widget 对象直接可读
```

**`test_config_dialog.py`** — 构造对话框后检查其内部结构：

```python
dlg = ConfigDialog(school_config=school, teacher_config=teacher, ...)
assert dlg.tabs.count() == 5
buttons = dlg._tab_adj.findChildren(QPushButton)
assert {btn.text() for btn in buttons} == {"調整を追加", "編集", "削除"}
```

**`test_tray.py`** — 调用 `update_status()` 后检查 tooltip 文字：

```python
tray.update_status(sc)
assert "初年次セミナーA" in tray.toolTip()   # QSystemTrayIcon 的属性
```

### 5.4 覆盖边界

| | 能发现 | 发现不了 |
|--|--------|---------|
| **内容** | 数据未正确传递到 widget（标签未更新、文字错误） | 字体大小、颜色是否视觉正确 |
| **结构** | 对话框结构被破坏（标签页数量变化、按钮被删） | 控件布局错位 |
| **状态** | 初始状态错误（不该可见的窗口 `isVisible()` 为真） | 用户点击、键盘操作的完整交互流程 |

本项目未使用 `qtbot.mouseClick` 等操作模拟方法，所有 GUI 测试均为**构造后读取属性**的静态验证。

## 7. 结论

CodeWidget 项目具备完整的自动化测试闭环：
1. **纯逻辑层**：采用标准单元测试，易于维护和扩展。
2. **GUI 层**：采用 `pytest-qt` 模拟真实 Qt 事件循环，确保 UI 逻辑在不同平台下行为一致。
3. **集成验证**：通过加载真实的 `school_config.json` 模板进行全链路测试。

这套体系为后续的重构和跨平台迁移提供了坚实的质量保障。
