# 07 平台差异说明

## 1. 概述

CodeWidget 同时支持 Windows 10/11 与 macOS。核心业务逻辑（调度引擎、出席码管理、配置模型）在两个平台上完全相同；平台差异仅集中在以下四个方面：

1. **窗口标志** — `Qt.WindowType.Tool` 的取舍
2. **配置文件路径** — 可写目录的计算逻辑
3. **构建与打包** — PyInstaller spec 的平台分支
4. **图标格式** — `.ico`（Windows）与 `.icns`（macOS）

---

## 2. 窗口标志差异

### 2.1 Qt.WindowType.Tool 标志

**Windows:**

```python
flags = Qt.WindowType.WindowStaysOnTopHint | Qt.WindowType.FramelessWindowHint
flags |= Qt.WindowType.Tool  # Windows only: hide from taskbar/Alt+Tab
```

- `Tool` 标志使窗口不出现在 Windows 任务栏
- `Tool` 标志使窗口不出现在 Alt+Tab 任务切换列表
- 这是期望行为：出席码展示窗口是辅助性浮动窗口，不应占据主任务管理界面

**macOS:**

```python
flags = Qt.WindowType.WindowStaysOnTopHint | Qt.WindowType.FramelessWindowHint
# macOS 上不加 Tool 标志
```

- 在 macOS 上添加 `Tool` 标志会导致窗口在切换应用时被隐藏（点击 Dock 切换到其他应用后出席码窗口消失）
- 这是 Qt/macOS 集成的特定行为：macOS 将 `Tool` 类型窗口视为"辅助面板"，当所属应用失去焦点时面板会随主应用一起隐藏
- 出席码窗口需要在教师切换到其他应用（如投影软件、浏览器）时保持可见，因此必须省略该标志

**代码实现（`src/gui/attendance_window.py`，第 38–41 行）:**

```python
def __init__(self, parent: QWidget | None = None) -> None:
    flags = Qt.WindowType.WindowStaysOnTopHint | Qt.WindowType.FramelessWindowHint
    if sys.platform != "darwin":
        flags |= Qt.WindowType.Tool  # Windows only: hide from taskbar/Alt+Tab
    super().__init__(parent, flags)
```

## 3. 配置文件路径差异

### 3.1 可写配置目录（`_user_data_dir()`）

**开发模式（两个平台相同）:**

`sys.frozen` 为 `False`，使用项目根目录：

```
<project_root>/config/
```

**Windows 打包后（`sys.frozen == True`，`sys.platform != "darwin"`）:**

```
<exe 所在目录>/config/
  例: C:\Users\teacher\Desktop\CodeWidget\config\
```

- `sys.executable` 直接指向 `CodeWidget.exe`
- `exe.parent` 即为配置目录的父目录，逻辑简单直接

**macOS 打包后（`sys.frozen == True`，`sys.platform == "darwin"`，`exe.parent.name == "MacOS"`）:**

```
CodeWidget.app 包内部结构:
  CodeWidget.app/
  └── Contents/
      ├── MacOS/
      │   └── CodeWidget   ← sys.executable
      ├── Resources/
      └── Info.plist

配置目录（.app 包外，与 .app 同级）:
  <包含 .app 的文件夹>/config/
  例: /Applications/config/
      ~/Desktop/config/
```

**macOS 路径计算逻辑（`src/main.py`，第 44–49 行）:**

```python
if getattr(sys, "frozen", False):
    exe = Path(sys.executable)
    if sys.platform == "darwin" and exe.parent.name == "MacOS":
        # .app/Contents/MacOS/CodeWidget → go up 4 levels → parent of .app
        return exe.parent.parent.parent.parent
    return exe.parent
return Path(__file__).parent.parent
```

路径层级拆解：

```
sys.executable           = .../CodeWidget.app/Contents/MacOS/CodeWidget
exe.parent               = .../CodeWidget.app/Contents/MacOS/
exe.parent.parent        = .../CodeWidget.app/Contents/
exe.parent.parent.parent = .../CodeWidget.app/
exe.parent.parent.parent.parent = .../<包含 .app 的文件夹>/  ← 返回值
```

**设计理由:** 将配置文件置于 `.app` 包外，使用户可以不重新安装就替换配置文件（例如每学年更新 `school_config.json`），也便于独立备份。Windows 上 exe 本身就位于可写目录，无需特殊处理。

### 3.2 只读资源路径（`_resource()`）

两个平台的处理方式相同，均通过 `sys._MEIPASS`（PyInstaller 解压临时目录）访问捆绑的只读资源：

```python
def _resource(rel: str) -> Path:
    if getattr(sys, "frozen", False):
        return Path(sys._MEIPASS) / rel  # PyInstaller 解压目录
    return Path(__file__).parent.parent / rel
```

捆绑的只读资源包括：`assets/icon.png`、`config/school_config.json`（模板）、`config/teacher_config.json`（模板）、`config/settings.json`（模板）。首次运行时这些模板被复制到 `_user_data_dir()/config/` 可写目录后供用户修改。

## 4. macOS LSUIElement（后台托盘应用）

`CodeWidget.spec` 在 macOS 构建时通过 `info_plist` 字典将 `LSUIElement` 设置为 `True`：

```python
# CodeWidget.spec，第 71–76 行
info_plist={
    "LSUIElement": True,             # hide from Dock (tray-only app)
    "NSHighResolutionCapable": True,
    "CFBundleShortVersionString": "1.0.0",
    "CFBundleVersion": "1.0.0",
},
```

- `LSUIElement = True` → 应用不出现在 Dock，也不出现在 Cmd+Tab 应用切换器
- 应用完全通过菜单栏托盘图标（Menu Bar Extra）操作
- 这与第 2 节的窗口标志决策相互配合：macOS 上省略 `Tool` 标志后，出席码窗口不会随应用失焦消失；同时 `LSUIElement` 又确保应用本身不占用 Dock 位置，保持纯托盘模式

**与 Windows 的对比:** Windows 上通过 `Qt.WindowType.Tool` 标志实现窗口不出现在任务栏；macOS 上则通过 `LSUIElement` 在系统层面隐藏整个应用的 Dock 入口。

## 5. 构建与打包差异

### 5.1 Windows 构建

**工具:** PyInstaller（直接运行 spec 文件）

```bash
uv run pyinstaller CodeWidget.spec --clean
```

**输出:** `dist/CodeWidget.exe`（单文件，`console=False` 无控制台窗口）

**图标格式:** `.ico`（`src/assets/icon.ico`，Windows 原生图标格式，支持多尺寸）

**启动:** 直接双击 `.exe` 运行

### 5.2 macOS 构建

**工具:** PyInstaller，通过 `build_macos.sh` 脚本驱动（两步骤）

```bash
./build_macos.sh
```

**输出:** `dist/CodeWidget.app`（标准 macOS 应用程序包）

**图标格式:** `.icns`（`src/assets/icon.icns`，Apple 原生图标格式）

**macOS 构建的两个阶段（来自 `build_macos.sh`）:**

**阶段一：生成 `.icns` 图标**

使用 macOS 内置的 `sips` 和 `iconutil` 工具（需要 Xcode Command Line Tools）将源 PNG 转换为多分辨率 `.icns`：

```bash
# 生成各尺寸切片（含 @2x Retina 版本）
sips -z 16   16   icon.png --out icon.iconset/icon_16x16.png
sips -z 32   32   icon.png --out icon.iconset/icon_16x16@2x.png
sips -z 32   32   icon.png --out icon.iconset/icon_32x32.png
sips -z 64   64   icon.png --out icon.iconset/icon_32x32@2x.png
sips -z 128  128  icon.png --out icon.iconset/icon_128x128.png
sips -z 256  256  icon.png --out icon.iconset/icon_128x128@2x.png
sips -z 256  256  icon.png --out icon.iconset/icon_256x256.png
sips -z 512  512  icon.png --out icon.iconset/icon_256x256@2x.png
sips -z 512  512  icon.png --out icon.iconset/icon_512x512.png
sips -z 1024 1024 icon.png --out icon.iconset/icon_512x512@2x.png
iconutil -c icns icon.iconset -o icon.icns
```

**阶段二：PyInstaller 打包**

```bash
uv run pyinstaller CodeWidget.spec --clean
```

spec 文件在 `darwin` 平台时额外执行 `BUNDLE()` 步骤，将 EXE 封装为标准 `.app` 包结构，并注入 `Info.plist`。

**代码签名:** 当前 spec 中 `codesign_identity=None`，未配置代码签名。在未签名状态下，macOS Gatekeeper 可能阻止首次运行，用户需在"系统设置 → 隐私与安全性"中手动允许。

### 5.3 spec 文件中的平台分支

`CodeWidget.spec` 在同一文件中处理两个平台：

```python
# 图标文件按平台选择
_icon = str(ROOT / "src" / "assets" / ("icon.icns" if _sys.platform == "darwin" else "icon.ico"))

# macOS 专用：将 EXE 封装为 .app 包
if _sys.platform == "darwin":
    app = BUNDLE(
        exe,
        name="CodeWidget.app",
        icon=str(ROOT / "src" / "assets" / "icon.icns"),
        bundle_identifier="com.sxwins.codewidget",
        info_plist={
            "LSUIElement": True,
            "NSHighResolutionCapable": True,
            ...
        },
    )
```

Windows 构建只生成 `EXE`；macOS 构建在 `EXE` 之上再执行 `BUNDLE`，输出 `.app` 包。

### 5.4 图标文件汇总

| 平台 | 格式 | 路径 | 说明 |
|------|------|------|------|
| Windows | `.ico` | `src/assets/icon.ico` | 含多尺寸（16/32/48/256px）的 Windows 图标 |
| macOS | `.icns` | `src/assets/icon.icns` | 由 `build_macos.sh` 生成，含全套 @2x Retina 尺寸 |
| 运行时（托盘） | PNG（动态生成） | `src/gui/icon.py` | `make_icon()` 在代码中动态生成托盘图标 |

## 6. 系统托盘差异

**Windows:**

- 托盘图标位于任务栏右侧通知区域（System Tray）
- 左键单击直接触发 `toggle_window`
- 右键显示上下文菜单

**macOS:**

- 托盘图标位于屏幕右上角菜单栏（Menu Bar Extra）
- 建议使用透明背景 PNG 图标，系统自动适配深色/浅色模式
- 单击行为与 Windows 相同（`toggle_window` / 上下文菜单）
- 由于设置了 `LSUIElement = True`，应用没有 Dock 图标，托盘图标是唯一的用户交互入口

---

## 7. 高 DPI / Retina 显示

**macOS Retina:**

- `NSHighResolutionCapable = True`（已在 `info_plist` 中设置）使应用感知 Retina 分辨率
- Qt 自动处理 HiDPI 缩放，逻辑像素坐标无需修改
- `.icns` 中包含 @2x 尺寸切片，确保图标在 Retina 屏幕上清晰

**Windows DPI 缩放:**

- Qt 在 Windows 上自动处理系统 DPI 设置（96/120/144 DPI 等）
- `window_scale` 配置项（30–300%）在 Qt 的自动缩放之上提供额外的用户级缩放控制，适用于两个平台

## 8. 差异汇总表

| 差异点 | Windows | macOS |
|--------|---------|-------|
| `Qt.Tool` 窗口标志 | 添加（隐藏出任务栏与 Alt+Tab） | 不添加（防止切换应用时窗口消失） |
| 配置文件位置（打包后） | `exe` 同级目录 `/config/` | `.app` 包外同级目录 `/config/` |
| 路径计算层级 | `exe.parent`（上移 1 级） | `exe.parent` × 4（上移 4 级） |
| 可执行文件格式 | `.exe`（单文件） | `.app` 应用程序包 |
| 图标格式 | `.ico` | `.icns`（需 `build_macos.sh` 预生成） |
| 托盘位置 | 任务栏通知区域 | 菜单栏右侧 |
| 隐藏应用的机制 | `Qt.Tool` 标志 | `LSUIElement = True`（`Info.plist`） |
| 代码签名 | 不需要 | 可选（Gatekeeper；当前未配置） |
| Retina 支持声明 | 不需要 | `NSHighResolutionCapable = True` |
| 专用构建脚本 | 无（直接运行 spec） | `build_macos.sh`（生成 `.icns` + 运行 spec） |
