## 1. 背景与问题

### 1.1 应用背景

学校现行出勤系统要求教师在课程开始前后的一段时间内，向学生展示"出勤码"。学生在既有出勤系统中输入该码以完成出勤登记。出勤码由既有系统生成，教师从中获取后手动展示给学生。

### 1.2 现存问题

目前各教师采用 PowerPoint 幻灯片、临时文本文件、手写展示等各自为政的方式呈现出勤码，存在以下痛点：

- **展示方式分散**：没有统一工具，每位教师各自处理，重复操作多。
- **易遗忘或时间不准确**：上课时容易忘记展示出勤码，或展示时机不在正确的窗口期内。
- **缺少自动提示机制**：现有方式无法按照课程时间表自动提醒教师何时需要展示出勤码。
- **投屏不便**：普通窗口容易被其他窗口遮挡，出勤码字体不醒目，投屏体验差。

### 1.3 解决方案概述

开发一个**轻量级桌面工具**，专注于出勤码的定时展示。该工具根据学期课表自动判断当前是否处于某门课程的出勤码展示窗口期，若是则弹出小型置顶窗口，供教师粘贴出勤码后展示给学生。

## 2. 功能范围

### 2.1 纳入范围（In Scope）

| 功能类别 | 具体内容 |
|----------|----------|
| 课表推导 | 基于全校通用学期课表与每日固定时限表，推导每门课每次上课的具体日期（第1回、第2回……） |
| 个人配置 | 教师以"周几第几限对应某课程名"的方式录入个人课程信息，生成并保存个人配置文件 |
| 自动展示 | 在开课前/后指定窗口期内，自动定位当前应显示的课程，并弹出出勤码展示窗口 |
| 展示窗口 | 小尺寸、可拖动、始终置顶的出勤码展示窗口，支持投屏使用 |
| 手动录入 | 教师手动输入或粘贴出勤码（出勤码来源为既有系统，本工具仅负责展示） |
| 课程调整 | 教师可查看并修改授课日/课时配置，处理停课、补课、调课等情况 |

### 2.2 排除范围（Out of Scope）

| 排除内容 | 说明 |
|----------|------|
| 学生侧功能 | 不负责学生身份验证、出勤登记、提交记录、统计报表等（由现有系统完成） |
| 系统对接 | 不与学校既有出勤系统进行接口对接，不自动获取出勤码，不自动提交出勤数据 |
| 特殊课表 | 本阶段不支持集中讲义、集中授课等特殊课表形态，仅处理常规周课表 |
| 网络功能 | 不依赖网络运行，不涉及云端同步或远程配置 |

## 3. 用户与使用场景

### 3.1 用户角色

本工具的唯一主要用户为**教师**。教师既是工具的配置者，也是运行时的操作者。

### 3.2 核心使用场景（7个）

以下7个场景构成本工具的完整使用生命周期：

**场景1：导入学期通用配置**

- 时机：学期开始前，或学校发布新学期课表后
- 操作：教师导入或配置全校通用的"学期课表文件"（含各星期几的实际授课日期列表）和"每日时限表"
- 说明：此配置通常可复用学校提供的模板，多数学期无需从零开始

**场景2：设置个人课程配置**

- 时机：学期开始前，或开始新课程时
- 操作：教师在工具中输入个人课程安排，例如"周一第2限：课程A；周三第3限：课程B"，并保存为个人配置文件
- 说明：工具应根据该配置与学期课表，自动推导出每门课的具体授课日期列表

**场景3：上课当天启动工具**

- 时机：上课前，通常为到达教室时
- 操作：教师启动工具，工具自动读取个人配置，进入监控状态

**场景4：窗口期自动弹出出勤码窗口**

- 时机：课程开始前10分钟至课程开始后30分钟（即显示窗口期内）
- 操作：工具自动检测当前时间，识别命中的课程，弹出对应的出勤码展示窗口
- 说明：无需教师手动操作，自动触发

**场景5：粘贴出勤码并展示给学生**

- 时机：出勤码窗口弹出后
- 操作：教师从既有出勤系统获取出勤码，将其输入或粘贴到工具窗口中；工具以大字体、高对比度方式展示该码
- 说明：窗口始终置顶、可拖动，便于在投屏画面中持续可见

**场景6：窗口期结束后自动待机**

- 时机：超过课程开始后30分钟（显示窗口期结束后）
- 操作：工具自动隐藏展示窗口，进入待机或后台状态（具体行为可配置）

**场景7：处理停课、补课或调课**

- 时机：当教师因出差、生病或其他原因需要调整授课安排时
- 操作：教师在工具的配置界面中查看授课日历预览，对特定日期执行停课/补课/调课操作，并保存
- 说明：调整仅影响本工具的展示逻辑，不影响学校官方课表；调整后工具的显示行为应立即与调整结果一致

## 4. 数据模型

本工具的数据分为三层：**全校通用配置（SchoolConfig）**、**教师个人配置（TeacherConfig）**、**运行时状态（Runtime State）**。

### 4.1 第一层：全校通用配置（SchoolConfig）

此层配置由学校层面决定，通常一个学期维护一次，供所有教师复用。

#### 4.1.1 学期课表

| 字段 | 类型 | 说明 |
|------|------|------|
| 学期名称 | 字符串 | 例如"2026年春季学期" |
| 学期起始日期 | 日期 | 例如 2026-04-01 |
| 学期结束日期 | 日期 | 例如 2026-07-31 |
| 各星期的授课日期列表 | 按星期几分组的日期数组 | 见下方说明 |

**授课日期列表的核心要求**：

由于祝日、学校活动日、休讲日等原因，实际授课日不能简单地以"每周"规律推导。因此，课表必须以**枚举方式**明确列出每个星期几对应的全部实际授课日期，例如：

```
周一授课日：[2026-04-06, 2026-04-13, 2026-04-27, ..., 2026-07-20]  （共14次）
周二授课日：[2026-04-07, 2026-04-14, 2026-04-21, ..., 2026-07-21]  （共14次）
...
周五授课日：[2026-04-10, 2026-04-17, ..., 2026-07-24]
```

这一列表是推导"每门课第几回对应哪个日期"的基础数据。

#### 4.1.2 每日时限表（Periods）

全校每天固定6个课时段（1限～6限），各时段的起止时间如下：

| 时限 | 开始时间 | 结束时间 |
|------|----------|----------|
| 1限 | 08:50 | 10:30 |
| 2限 | 10:40 | 12:20 |
| 3限 | 13:10 | 14:50 |
| 4限 | 15:00 | 16:40 |
| 5限 | 16:50 | 18:30 |
| 6限 | 18:40 | 20:20 |

说明：时限表全校统一，正常情况下整个学期固定不变。

### 4.2 第二层：教师个人配置（TeacherConfig）

每位教师维护自己的个人配置文件，内容包括：

#### 4.2.1 课程列表

每门课程记录以下信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| **课程唯一ID** | 字符串 | 系统核心标识符（如 `EEE1000411`）。用于关联调整记录（Override）和出勤码存储（键格式 `{course_id}_{session_key}`）；同一教师的配置文件中不得重复 |
| 课程名称 | 字符串 | 例如"计算机导论"、"数据结构"，用于展示窗口显示 |
| 课程代码 | 字符串（可选） | 学校官方课程代码，仅用于记录 |
| 上课星期 | 字符串 | "Monday"/"Tuesday"/"Wednesday"/"Thursday"/"Friday" |
| 上课时限 | 整数（1～6） | 对应时限表中的课时段编号 |

示例：

```
课程A：周一 第2限
课程B：周三 第3限
课程C：周五 第1限
```

#### 4.2.2 例外调整记录（Overrides）

教师可记录对个别授课日的调整，每条调整记录包含：

| 调整类型 | 必填字段 | 说明 |
|----------|----------|------|
| 停课（Skip） | 课程名、原授课日期 | 标记该日期不授课 |
| 补课（Makeup） | 课程名、补课日期、补课时限 | 新增一次授课 |
| 调课（Reschedule） | 课程名、原授课日期、新授课日期、新时限 | 将某次课从原时间移至新时间 |

所有调整记录应与课程列表存储在同一个个人配置文件中，且格式为可手动编辑的纯文本（JSON）。

### 4.3 第三层：运行时状态（Runtime State）

运行时状态不持久化（或仅部分持久化），由程序在运行期间动态维护：

| 状态项 | 说明 |
|--------|------|
| 当前日期时间 | 实时获取系统时间 |
| 当前命中的课程 | 根据时间判断当前处于哪门课的显示窗口期（可能为空） |
| 当前出勤码文本 | 教师在本次窗口期内输入/粘贴的出勤码 |
| 窗口位置 | 用户拖动后的窗口坐标，下次启动时恢复（持久化） |
| 窗口显示/隐藏状态 | 当前展示窗口是否可见 |

## 5. 核心业务规则

### 5.1 授课日推导规则

**输入**：
- SchoolConfig 中某星期几的授课日期列表
- TeacherConfig 中某课程对应的上课星期与时限

**输出**：
- 该课程的"授课日期列表"，按时间顺序排列，依次编号为第1回、第2回……
- 支持反向查询：给定某一日期，返回对应第几回（若该日有该课）

**规则说明**：

1. 从 SchoolConfig 中取出该课程对应星期几的授课日期列表。
2. 将该日期列表作为该课程的基础授课日序列，以升序排列。
3. 在应用例外调整之前，第 N 个日期即为该课程的"第 N 回"（基础回次）。
4. 应用例外调整后，按第 5.6 节规则重新确定实际授课回次（见"调整对第几回编号的影响"）。

**限制**：本阶段仅支持普通周课表，不支持集中讲义或其他特殊排课。

### 5.2 显示窗口规则

对每门课程在每个授课日，显示窗口定义如下：

```
课程开始时间 = 该授课日对应时限的开始时间（来自时限表）

显示窗口开始 = 课程开始时间 − pre_class_minutes（默认 10 分钟）
显示窗口结束 = 课程开始时间 + post_class_minutes（默认 30 分钟）
```

> **参数说明**：`pre_class_minutes` 和 `post_class_minutes` 是可配置参数，存储于 `teacher_config.json` 的 `settings` 字段（见第4节数据模型）。默认值分别为 10 分钟和 30 分钟，教师可根据需要调整。

**判断逻辑**：

- 当系统当前时间落在某门课的显示窗口内时（即 `窗口开始 ≤ 当前时间 ≤ 窗口结束`），该课程被"命中"，工具应显示该课程的出勤码展示窗口。
- 时间检测应以轮询方式持续进行（建议检测频率：每30秒或每分钟一次），以响应时间边界的跨越。

**示例**：

若教师某门课安排在周三第3限（13:10 开始），则该课在周三的显示窗口为：

```
窗口开始：13:00（13:10 − 10分钟）
窗口结束：13:40（13:10 + 30分钟）
```

即每到上课的那个周三，系统时间在 13:00～13:40 之间时，工具自动显示该课的出勤码窗口。

### 5.3 多课程冲突处理

正常情况下，同一时刻不应有多门课同时命中（因同一时限不能同时上两门课）。但若教师配置有误（例如同一时限配置了两门课），系统应按以下规则确定性地选择一门课显示：

**优先级规则**（按优先级从高到低）：

1. 优先显示"显示窗口开始时间与当前时刻绝对差值最小"的课程（即窗口开始时间最接近当前时刻的课程）。
2. 若仍相同，优先显示时限编号更小的课程（例如第2限优于第3限）。

规则必须确保结果的确定性，避免展示内容来回跳动。

### 5.4 非窗口期行为

当系统当前时间不在任何课程的显示窗口内时：

- **默认行为**：工具隐藏出勤码展示窗口，进入待机状态（系统托盘图标保持可见）。
- **手动覆盖（可选）**：允许教师通过托盘图标或菜单手动打开展示窗口，以应对临时情况（如课表外的临时讲解）。
- 待机状态下，工具应继续在后台运行并持续检测时间，以便在下一个窗口期到来时自动弹出。

### 5.5 出勤码录入规则

- 出勤码由教师从学校既有出勤系统手动获取，然后输入或粘贴到本工具的展示窗口中。
- 本工具**不校验**出勤码的格式或有效性，**不上报**任何数据，仅负责展示。
- 出勤码文本框应支持直接粘贴操作，并提供一键清空功能（可选）。
- 出勤码展示后，应以醒目方式呈现（大字体、高对比度），便于学生在投屏画面中辨认。

### 5.6 课程调整规则

#### 5.6.1 停课（Skip）

- **触发条件**：教师将某门课在某个授课日标记为"停课"。
- **展示行为**：该日期不再触发显示窗口，即使系统时间进入原窗口期，也不弹出展示窗口。
- **即时生效**：若停课标记是在显示窗口期已开始后才录入的，工具应立即隐藏当前展示窗口并进入待机状态。

#### 5.6.2 补课（Makeup）

- **触发条件**：教师为某门课新增一个非常规授课日期及其对应时限。
- **展示行为**：在补课日期的显示窗口期内（补课时限开始前10分钟至开始后30分钟），工具应自动触发该课程的展示窗口。
- **补课时限范围**：1限至6限均可指定。

#### 5.6.3 调课（Reschedule）

- **定义**：将某一次授课从"原日期+原时限"调整到"新日期+新时限"。
- **等价语义**：调课在逻辑上等价于"对原日期执行停课 + 对新日期执行补课"。
- **界面呈现**：应作为单一操作呈现（而非分两步操作），以便教师理解和回溯。
- **原时限处理**：原时限在调课记录中用于标识被调整的是哪一次课，新时限决定新窗口期的计算基准。

#### 5.6.4 调整对第几回编号的影响

调整操作会影响课程的"实际授课回次"编号，规则如下：

- 回次编号以**实际授课发生的顺序**为准，在应用全部停课/补课/调课调整后，对实际发生的授课日期按时间升序重新编号。
- 具体逻辑：
  1. 取基础授课日期列表（来自 SchoolConfig 中该星期几的日期序列）。
  2. 移除所有被标记为停课的日期。
  3. 将调课的原日期替换为新日期（在对应位置移除原日期，加入新日期）。
  4. 加入所有补课日期。
  5. 对上述合并后的日期集合按升序排列，依次编号为第1回、第2回……
- 工具应提供回次预览功能，帮助教师确认调整后各回次对应日期是否正确。

## 6. 功能需求

### 6.1 配置管理

| 需求编号 | 需求描述 | 优先级 |
|----------|----------|--------|
| F-CM-01 | 支持加载全校通用配置文件（学期课表 + 时限表，JSON格式） | 必须 |
| F-CM-02 | 支持加载和保存个人配置文件（课程列表 + 槽位，JSON格式） | 必须 |
| F-CM-03 | 支持通过界面表单新增、编辑、删除课程条目（课程名、星期、时限） | 必须 |
| F-CM-04 | 支持通过界面查看、新增、删除授课调整记录（停课/补课/调课） | 必须 |
| F-CM-05 | 配置文件使用纯文本JSON格式，支持手动编辑和跨平台移植 | 必须 |

### 6.2 运行时监控与触发

| 需求编号 | 需求描述 | 优先级 |
|----------|----------|--------|
| F-RT-01 | 启动后自动进入监控状态，持续检测当前时间与课程窗口期的匹配关系 | 必须 |
| F-RT-02 | 命中窗口期时自动弹出展示窗口；窗口期结束后自动隐藏展示窗口 | 必须 |
| F-RT-03 | 展示逻辑综合基础课表与调整记录，调整记录优先于基础课表 | 必须 |
| F-RT-04 | 展示窗口中应显示课程名称与第几回（当前实现显示课程名 + "第X回"） | 必须 |
| F-RT-05 | 支持显示距下一课开始的倒计时（可选） | 可选 |

### 6.3 出勤码展示窗口

| 需求编号 | 需求描述 | 优先级 |
|----------|----------|--------|
| F-DW-01 | 提供文本框允许教师输入/粘贴出勤码 | 必须 |
| F-DW-02 | 出勤码以大字体、高对比度方式展示，确保投屏可辨认 | 必须 |
| F-DW-03 | 展示窗口始终置顶（Always-on-top），不被其他窗口遮盖 | 必须 |
| F-DW-04 | 展示窗口可用鼠标拖动，位置在退出后记忆并在下次启动时恢复 | 必须 |
| F-DW-05 | 提供一键清空出勤码的功能 | 可选 |
| F-DW-06 | 在排课预览界面，支持为当前课程的全部回次一键生成随机4位数字出勤码（0000–9999），并可在保存前逐条修改 | 建议 |

### 6.4 授课日历预览与调整

| 需求编号 | 需求描述 | 优先级 |
|----------|----------|--------|
| F-CA-01 | 提供每门课的授课日历预览，展示第1回～第N回对应的具体日期 | 必须 |
| F-CA-02 | 预览中应区分显示基础授课日、停课日、补课日、调课后的新日期 | 建议 |
| F-CA-03 | 支持通过界面添加调课（Reschedule）记录；停课（Skip）和补课（Makeup）可直接编辑 JSON 文件录入 | 必须 |
| F-CA-04 | 调整操作后预览应即时更新，反映最新的回次排列 | 必须 |
| F-CA-05 | 支持删除某条已有的调整记录（恢复至基础课表状态） | 必须 |

## 7. 界面需求

### 7.1 出勤码展示小窗口（核心界面）

此为工具的核心交互界面，在上课窗口期内对教师和学生可见。

**布局与样式要求**：

- 整体尺寸小（建议宽度不超过屏幕宽度的25%），仅占屏幕一小块区域
- 出勤码文字应使用超大字体（建议字号不小于48pt），高对比度配色（如白底黑字或黑底白字）
- 显示当前课程的基本信息：课程名、今天是第几回（当前实现不显示日期）
- 不应包含复杂控件，界面极简，减少视觉干扰

**交互要求**：

- 始终置顶，不被其他窗口遮盖
- 可用鼠标任意拖动，位置记忆并在重启后恢复
- 不抢占输入焦点（不影响教师使用其他软件）
- 提供出勤码输入区（可输入/粘贴）和清空按钮

### 7.2 配置界面（非授课时使用）

此界面仅在课前配置阶段使用，不要求极简，可以稍复杂。

**基本配置区**：

- 显示并支持加载当前使用的全校通用配置文件路径
- 提供表单操作课程列表：新增课程、编辑课程名/星期/时限、删除课程
- 配置保存按钮，支持另存为新文件

**授课日历预览区**：

- 选择某门课后，展示该课第1回至第N回的日期列表
- 标注哪些日期有调整（停课/补课/调课），调整后的实际回次如何排列
- 支持点击某个日期进行调整操作

**调整记录管理区**：

- 以列表形式展示所有已有的调整记录（类型、课程、原日期、新日期等）
- 支持新增调整（选择类型后填写相应字段）
- 支持删除某条调整记录
- 必须明确提示：调整仅影响本工具的展示逻辑，不影响学校官方课表

### 7.3 系统托盘

- 工具启动后在系统托盘显示图标
- 托盘图标提供菜单，包含：打开配置界面、手动显示/隐藏展示窗口（可选）、退出
- 关闭展示窗口时，工具应进入托盘待机状态而非直接退出

## 8. 技术要求

### 8.1 编程语言与框架

- 推荐使用 **Python**（开发效率高，GUI 生态成熟，适合此类轻量工具）
  - GUI 框架：首选 **PySide6** 或 **PyQt6**（Qt 原生支持置顶窗口、可拖动、系统托盘）
- 备选使用 **C++**，同样采用 **Qt6** 框架

### 8.2 跨平台支持

| 平台 | 要求 | 发布格式 |
|------|------|----------|
| Windows 10/11 | 必须支持 | 独立 `.exe`（PyInstaller 或 Qt 部署工具打包） |
| macOS（近3个版本） | 必须支持 | 独立 `.app` 应用包 |

- 不得依赖平台特有 API；所有 GUI 操作、文件操作均使用跨平台接口
- Windows 和 macOS 上的功能与界面应保持一致

### 8.3 依赖与分发

- 最终发布的可执行文件应为**独立包**，用户无需手动安装 Python 运行环境或任何第三方库
- 配置文件格式：**JSON 纯文本**，支持手动编辑，跨平台可移植（换电脑拷贝配置文件即可使用）

### 8.4 性能与稳定性

- 启动速度快，工具从启动到就绪应在3秒内完成
- 时间轮询逻辑应对系统休眠/唤醒、时钟调整保持鲁棒，不得因此崩溃或产生错误弹窗
- 内存占用低，长时间后台运行不得造成内存持续增长

### 8.5 可维护性

- 配置文件结构清晰，字段命名有意义，格式文档化
- 核心业务逻辑（课表推导、窗口判断、回次计算）应与 GUI 层分离，便于单元测试
- 代码注释应覆盖关键业务逻辑

## 9. 验收标准

以下7条验收标准对应第3节的7个核心使用场景，全部满足则视为交付合格：

| 编号 | 验收项 | 验收方式 |
|------|--------|----------|
| AC-01 | 教师能通过界面以"周几第几限→课程名"的方式配置个人课程，并保存为JSON文件；重启后配置能正确加载 | 手动测试 |
| AC-02 | 工具能基于学期课表正确推导某门课的全部授课日期，并通过预览界面逐回展示（第1回、第2回……），与预期日期一致 | 手动对比 / 自动测试 |
| AC-03 | 在开课前 N 分钟至开课后 M 分钟内（N/M 默认为 10/30，可配置），工具能自动弹出对应课程的置顶展示小窗；窗口期外不弹出 | 手动测试（可调整系统时间辅助验证） |
| AC-04 | 展示小窗始终置顶（不被其他窗口遮盖）、可用鼠标拖动、占用屏幕面积小；关闭后位置能在下次启动时恢复 | 手动测试 |
| AC-05 | 教师可在小窗中粘贴出勤码，出勤码以大字体、高对比度方式展示，在投屏画面中清晰可辨 | 手动测试（实际投屏验证） |
| AC-06 | 超过窗口期后，展示小窗按预期自动隐藏/进入待机，工具继续在托盘运行，下一窗口期到来时再次自动弹出 | 手动测试 |
| AC-07 | 教师能在配置界面查看授课日历预览，并对特定日期执行停课/补课/调课操作；操作保存后，工具的展示逻辑按调整结果生效，预览中的回次编号正确更新 | 手动测试 / 自动测试 |
