# CodeWidget 自动测试实施说明及报告

本文档描述了 CodeWidget 项目的自动化测试体系架构、测试覆盖范围以及当前的测试状态。

## 1. 测试技术栈

项目采用了现代 Python 测试工具链，保证了代码质量和跨平台稳定性：

| 组件 | 技术 / 库 | 职责 |
|------|-----------|------|
| **测试框架** | `pytest` | 核心测试运行器，支持断言、Fixtures 等 |
| **GUI 测试** | `pytest-qt` | 提供 `qtbot` 用于在测试环境下安全地创建和操作 PySide6 控件 |
| **依赖管理** | `uv` | 管理虚拟环境，确保测试在隔离且一致的环境中运行 |
| **导入配置** | `pyproject.toml` | 通过 `pythonpath = ["src"]` 确保源代码对测试可见 |

## 2. 测试目录结构

测试代码位于 `tests/` 目录，与业务逻辑（`src/`）一一对应：

```
tests/
├── test_scheduler.py       — 排课引擎核心逻辑测试
├── test_override.py        — 调课规则应用与重编号测试
├── test_attendance_window.py — 出勤码展示窗 GUI 逻辑测试
├── test_config_dialog.py   — 设置对话框 UI 行为测试
├── test_tray.py            — 系统托盘状态更新测试
└── __init__.py
```

## 3. 测试覆盖范围

### 3.1 核心引擎逻辑 (Engine Logic)
- **Resolved Course Schedule**: 验证不同课程类型（春/秋/Q系）生成的授课次数（14次）和日期的准确性。
- **Override Application**: 验证停课（skip）、补课（makeup）、调课（reschedule）规则被正确应用，并确认 `session_key` 在调课后能正确重新编号。
- **Window Computation**: 验证课前/课后显示窗口的计算（默认 10/30 分钟）以及活动课程的命中逻辑。

### 3.2 界面交互 (GUI Interaction)
- **AttendanceWindow**: 验证课程信息（课程名、回次）是否正确渲染到标签和输入框中；验证窗口创建后初始为隐藏状态。
- **ConfigDialog**: 验证对话框可成功实例化；验证标签页数量（5个）、课程表列数（5列）、年度列内容（"2026"）；验证调整标签页的操作按钮集合（"調整を追加"、"編集"、"削除"）。不包含用户操作模拟（无 `qtbot.mouseClick`）和保存流程测试。
- **TrayIcon**: 验证托盘 ToolTip 随课程状态（无课/有课）的动态变化。

- **运行命令**: `uv run pytest -v`
- **结果摘要**:
    - **Total Tests**: 38

    - **Failed**: 0
    - **Execution Time**: ~2.33 秒

## 5. 结论

CodeWidget 项目具备完整的自动化测试闭环：
1. **纯逻辑层**：采用标准单元测试，易于维护和扩展。
2. **GUI 层**：采用 `pytest-qt` 模拟真实 Qt 事件循环，确保 UI 逻辑在不同平台下行为一致。
3. **集成验证**：通过加载真实的 `school_config.json` 模板进行全链路测试。

这套体系为后续的重构和跨平台迁移提供了坚实的质量保障。
