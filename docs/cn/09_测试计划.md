## 1. 测试目标

验证 CodeWidget 的核心业务逻辑（排课算法、调课规则、显示窗口计算）及关键 GUI 控件在构造和状态更新后的行为符合规格说明书（`03_调度逻辑规格.md`、`05_界面规格.md`）。

---

## 2. 测试范围

### 2.1 纳入范围

| 模块 | 测试类型 | 说明 |
|------|---------|------|
| `engine/scheduler.py` | 单元测试 | 排课生成、显示窗口计算、活动课程查找 |
| `engine/override.py` | 单元测试 | skip / makeup / reschedule 规则及 session_key 重编号 |
| `models/` | 隐式验证 | 通过加载真实配置文件间接验证序列化逻辑 |
| `gui/attendance_window.py` | 控件测试 | 标签更新、出席码显示、初始可见性 |
| `gui/config_dialog.py` | 控件测试 | 对话框结构（标签页、列数、按钮） |
| `gui/tray.py` | 控件测试 | 托盘图标 ToolTip 文字 |

### 2.2 排除范围

| 排除项目 | 排除理由 |
|---------|---------|
| `main.py` 主集成流程 | 涉及完整 Qt 事件循环和闭包内部状态，难以单元化 |
| 错误处理路径 | JSON 解析失败、文件不存在等异常分支未覆盖 |
| 配置文件读写（`save_*`） | I/O 测试未实现 |
| macOS 平台行为差异 | 当前测试仅在 Windows 11 执行 |
| 视觉外观（字体渲染、布局） | 属于非功能性测试，当前不纳入 |
| 用户交互模拟（点击、键盘） | `qtbot.mouseClick` 等操作模拟未使用 |

## 6. 风险评估

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|---------|
| `main.py` 集成层无自动化覆盖 | 高 | 启动流程、信号连接的缺陷无法自动发现 | 手动冒烟测试 |
| 测试数据与真实数据强耦合 | 中 | `邵_teacher_config.json` 变更可能导致测试失败 | 锁定测试用配置文件，不随业务数据更新 |
| 无 CI/CD 流水线 | 中 | 提交代码后不会自动触发测试 | 依赖开发者手动执行 |
| 仅在 Windows 执行测试 | 低 | macOS 专属代码路径（`Tool` 标志、`.app` 路径）未经自动测试 | 手动在 macOS 进行验收测试 |
| GUI 测试为非视觉静态验证 | 低 | 布局错位、颜色错误等视觉缺陷无法自动检测 | 通过手动验收补充 |

## 7. 退出准则（Exit Criteria）

满足以下全部条件方可视为测试通过：

1. ✅ 全部 38 件自动化测试通过（`38 passed, 0 failed`）
2. ✅ 无 P1 级别（阻断性）缺陷遗留
3. ✅ 核心路径（排课算法 + 调课规则 + 显示窗口计算）测试通过率 100%
4. ⚠️ 已记录的测试盲区（`main.py`、错误处理）在项目 `TECHNICAL_DEBT.md` 或测试报告中有明确说明
